# 追加层部分重叠：规则与验收

任务日期：2026-10-16。以 [组合规格 v2.1](architecture-composition.md) 为合同。目标是让社区追加模块能确定性组合，而不是按插件整包决定输赢。

## 生效规则

| 情况 | 行为 |
|---|---|
| A 提供 X/Y，B 提供 X/Z | 只裁决 X；A 的 Y 和 B 的 Z 均保留 |
| 同一个完整实现均用 replace | 较高层生效，其余该目标的贡献被遮蔽；不关闭作者的其他目标 |
| 同一个服务均用 wrap | A 包装默认，B 包装 A；各自新增方法与未修改方法保留；调用下层须显式合作 |
| replace 后再 wrap | 先抛弃被新 replace 遮蔽的旧链，再包装新实现 |
| 同一页的不同文件 | 可以组合；同一文件选择较高层，其余文件保留 |
| 较高层替换整个页面或外壳 | 低层针对其内部文件的覆盖也被压住，避免混入旧代码；同层/更高层显式覆盖有效 |
| 停用/移除上层或中间层 | 新代按目标恢复下一候选，独立贡献不被连带删除 |
| 同 order | 按目录名确定性排序，并在诊断中标记优先级相同 |
| 包装器异常、缺依赖、缺导出 | 明确失败并清理已登记资源，不留下半启动状态或假装成功 |

包装清单使用 `version:2`，旧的 `version:1` 完整替换仍有效。未知版本拒绝。旧程序会拒绝 version2，避免错误调用包装器。两个互不兼容的完整函数、HTML 页面或脚本文件无法自动推断作者意图并融合，应拆成更细目标或显式采用包装接口。

这里的 `version:2` 专指 `overrides/*/composition.json`；它不是普通 `skill.json/plugin.json` 的 `apiVersion`，不要求现有市场包统一升级 SDK 版本。

## 实测覆盖

- **176：8 项测试**。包括 A/B/C 的 48 种排列与启用子集；被遮蔽的共享实现与仍选中的独立导出；版本/目标/别名校验；私有字段与冻结接收者；真实 HTTP 的同页样式冲突和其他脚本保留；鉴权诊断不泄露文件路径或路由配置。
- **177：9 个磁盘组合代**。两层/三层、顺序颠倒、同优先级、停用、目录移除、回退默认；页面/外壳/共享图标与独立页面、资产均经真实 HTTP 验证。可选实际浏览器验证交互、RPC、opaque iframe 隔离和普通插件不可冒充管理页。选中的文件缺失时不拼接旧版文件。
- **178：17 项测试**。A/B/C 全部六种移除顺序；相交路由与独立路由、不同 HTTP 方法、正则及通配符；失败回滚、并发清理、清理报错、父级取消、取消重入和监听释放；重复验证 token/Origin/JSON/体积与重置守卫。
- **179：2 项测试、6 个实际应用代**。追加文件经正式 `createApplication` 驱动真实入站、消息仓及控制台；独立方法与共同增强都可观察；停用/移除 B、完整替换、移除旧 A、恢复默认。每代资源逆序且只清理一次，新代构造前旧代已清理；异步包装失败时未创建内核。

修复了两类真实问题：旧层单文件覆盖越过新层整页边界；路由资源挂在全局生命周期，导致单组撤销/失败后资源遗留。本轮改为带层次来源的 UI 裁决和独立路由子作用域；撤销父级登记时也释放清理闭包引用。

附带对齐 `.woff` 资产的清单校验与服务端解析，避免合法字体追加在加载阶段被拒绝；176 经真实 HTTP 验证。

## 诊断与限制

`node scripts/inspect-composition.mjs` 只预检磁盘计划；受鉴权的 `GET /api/composition` 返回运行代的实际选择、完整来源链、冲突决议及同优先级提示。两者不执行对方的模块，也不暴露原生函数、绝对文件路径或路由私有设置。

有状态组件切换仍需完整重启。新增测试使用独立临时应用、合成消息、被动传输及临时本机服务，没有调用真实模型、外发消息或公开服务。普通市场包不会自动取得管理员原生启动组合权限。

部分既有回归使用工作区扩展，日志仍记录 `image-generate` 的 `log is not a function`：该已安装技能声明 API1，却调用旧函数式 `log`。这在此前组合基线已存在，本轮没有修改该第三方技能；组合测试通过不等于它的生图功能已通过，也不等于真实 QQ 或商业模型联调通过。
