# 刷新策略与会话事件合批

复读0.4的动态`ui.refreshMs`及会话列表刷新后，0.5保留精确展示时钟、任务校正和日志流各自的调度职责。配置不是所有计时器的共同帧率。

| 原子行为 | 当前默认实现 |
| --- | --- |
| 动态配置 | `panels/refresh-policy.js`保存本宿主文档的数值策略，默认15000ms，最小1000ms，向下取整，最大2147483647ms。拒绝对象、数组和非有限值，避免溢出变成高速循环。 |
| 宿主消费 | 状态轮询读取当前策略，单飞与尾读；配置更新SSE只合并读取配置，不额外发起状态及QQ进程查询。已过时的普通轮询配置不能覆盖更新。 |
| 面板消费 | 宿主发送`refresh-policy`，注册握手补发当前值；panel-client先缓存再通知，避免模块晚加载丢失启动策略。会话的权威读取与心跳阈值动态跟随，改配置不重载iframe。 |
| 精确展示 | 等待期限仍由本地100ms时钟展示；记忆任务保持独立策略，日志保持增量流。倒计时不能因降低后台读取频率而冻结。 |
| 会话事件 | `sessions/session-events.js`把80ms内事件合并为只读列表校正，最大256个ID，溢出折为全量标记。单飞过程中保留尾批，空闲不持有周期timer，后台缓冲、前台恢复、离页清理。 |
| 详情与跟随 | 列表批次不被旧详情慢请求阻塞；同详情读取合并补读，不同选择独立进行。自动跟随记住实际事件ID，即使时间戳相同、ID队列溢出，也不按列表首项误选。失效选择/详情代际不得回写新界面。 |

共享策略、会话活动与事件队列都是独立默认UI资产，可通过`ui.assets`追加替换。202实际分别追加策略和队列文件，验证既有消费者使用所选实现；没有硬编码另一条默认导入旁路，也没有给会话页扩大配置写权限。
