# 追加式组合 v2：实现与回归证据

任务日期：2026-10-16。架构合同见 [architecture-composition.md](architecture-composition.md)。

## 实现范围

- 桌面和 headless 均通过 `createApplication()` 解析追加层，再创建业务对象。桌面缓存打开前的配置/人设/重置预处理也使用同一份选中计划。
- `bundled/runtime-defaults/components.js` 提供 52 个默认实现。覆盖状态仓、编排、唤醒策略、提示词、Runner、LLM、发送、扩展宿主及控制台装配。
- 页面按 id 接管、外壳替换、单个图标/样式/组件资产替换；普通插件仍不能冒充可信管理页面。
- 新增后端控制器与显式替换默认接口；作用域撤销恢复前一处理器。异步注册先完成再监听，失败回滚。
- 一代资源共享取消信号，逆序清理；启动/清理错误均保留。重置撤销追加路由并保留默认诊断接口。
- 选中的提示词同时进入实际运行与预览；选中的价格/费用逻辑同时进入持久统计与控制台读取。

## 规格同步与使用

相邻 `dsh-spec/DSH-ARCH.md` 已更新为 v2，`SPEC.md` 增加功能归属解释；旧版原件位于证据目录的 `spec-before/`，写入前后校验散列。

可运行示例在 [examples/composition](../examples/composition/README.md)。追加到 `overrides/<层目录>/` 后完整重启生效；移除或禁用后完整重启恢复默认。市场插件不自动升级为能够替换整个运行时的可信启动模块。

既有全量测试仍有部分历史夹具从工作区加载用户扩展；本轮日志中可见现有 `image-generate` 的 `log is not a function` 兼容错误。该扩展错误不应被全量测试的退出码掩盖，也不作为“所有已安装扩展已实机验证”的证明；本次新增组合验收均使用独立副本。真实账号联调、原生安装包和发布不属于本轮结果。
