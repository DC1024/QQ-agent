## 判定与证据规则

1. 源码索引只提供定位，不等于语义审查或功能完成。同名函数、同名配置项、存在API或测试通过均不能单独证明端到端对等。
2. 每个原子项记录0.4触发入口、输入/默认值、状态变化、持久化、退出/失败/并发行为；再追踪0.5真实消费者，不能只检查字段或注册表。
3. 判定分为保留0.5、迁入、改良后迁入、明确舍弃及待核对；舍弃必须说明旧实现为何较差。用户新裁决优先，如删除沿用渐进点击，不恢复旧confirm。
4. UI能力落入默认模块/可替换资源；后端与业务沿用当前组合组件、控制器、能力提供者。不得为迁移重新引入全局页面状态、直传宿主令牌或固定核心旁路。
5. 数据验证必须含实际保存后重读及真实界面；交互验证包含键盘、退出、刷新、失败和并发。只用临时合成数据，不读取旧版账号/凭据或操作当前控制台。
6. 最终在全部原子项有具体判定及证据后，冻结源码运行完整回归；本目标不能以当前几项增量测试替代收口。
