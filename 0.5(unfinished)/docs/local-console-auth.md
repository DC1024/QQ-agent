# 本机控制台自动认证

本机浏览器打开 `/` 或 `/index.html` 时，宿主自动领取当前实例的控制台令牌；刷新、关闭后重开页签、旧缓存过期及服务重启不再要求日常手工输入。原生桌面窗口仍使用受主窗口、主frame和精确origin限制的IPC。普通API及SSE仍逐请求验证令牌和来源。

## 默认 HTTP 实现的入口

`POST /api/console/bootstrap` 是宿主专用的只读入口，响应只含 `{token}`，不读取配置文件、不写Cookie、不返回其它配置。响应使用 `Cache-Control: no-store`、`Referrer-Policy: no-referrer` 和 `nosniff`，不开放CORS。以下条件同时满足才可领取：

| 项目 | 条件 |
| --- | --- |
| 对端 | socket地址为回环地址 |
| Host | `127.0.0.1`、`localhost`或`[::1]`，端口精确匹配当前监听端口；HTTP默认80允许规范化省略端口 |
| Origin | 精确为当前HTTP origin，拒绝缺失和`null` |
| Referer | 同一origin，路径为`/`或`/index.html`，无URL用户名和密码 |
| Fetch Metadata | site为`same-origin`，mode为`same-origin`或`cors`，dest为`empty` |
| 意图头 | `x-qq-agent-bootstrap: 1` |

宿主fetch显式使用`mode: same-origin`、`credentials: omit`、`cache: no-store`及`referrerPolicy: same-origin`。后者只为此请求提供严格来源判定，静态资源原来的不发送Referer策略不变。缺失元数据的客户端继续使用原令牌方式。GET、OPTIONS、外部网页、opaque面板和普通本地脚本请求不会因缺少凭据而放行；后台其它路由不获得来源豁免。

这是浏览器来源边界，依赖不可信面板继续保持opaque sandbox，不能用请求头作为对本机原生进程的密码学身份认证。可信启动追加层仍可替换HTTP默认组件；普通市场插件不能借此扩大权限。

所有`/panels/u/`资源同时附带`Content-Security-Policy: ...; sandbox allow-scripts`，因此用户插件HTML、SVG即使被直接作为顶层页面打开，也保持opaque origin。仅依赖宿主iframe的sandbox并不足够：普通同源页面脚本可以改变history或指定同源referrer；响应层隔离防止这种直接打开的页面冒充根控制台。宿主根页面不受这项sandbox限制。

安全判定不依赖浏览器禁止History改写。实际Chromium允许该opaque页面把地址路径改为根路径，但其安全origin仍为`null`、存储仍拒绝，bootstrap的Origin/Fetch Metadata守卫仍须拒绝；相关负测应在改写后继续尝试领取，不能只检查地址栏或空白页面。

## 连接与生命周期

每次浏览器加载优先自动领取，旧的30分钟`sessionStorage`仅作为旧服务/自动入口不可用时的兼容回退，不改为永久明文缓存，不向`localStorage`、iframe URL或消息写入令牌。显式URL令牌仍先清除查询参数；显式错误凭据在验证前不静默切换身份，保留诊断语义。

仅宿主共享API/SSE连接显式启用自动恢复。普通鉴权守卫返回401及`CONSOLE_AUTH_REQUIRED`时，多个并发失败合并为一次领取；成功更新共享API/SSE并最多重试一次原API请求。业务处理器自己的401不会重放写操作；令牌管理、手动恢复中的候选ApiClient不启用此功能，错误候选始终真实失败。

令牌轮换后旧REST和SSE凭据立即失效，旧SSE关闭，顶层控制台重新领取当前值并连接，保留当前iframe和未保存输入。网络断开沿用SSE退避重连，不清空当前面板。手动更新、A-B-A值复用及页面销毁都使用代际校验取消旧领取；延迟401或bootstrap回复不能覆盖新身份。请求取消/超时后不重放，自动领取也受5秒上限约束。

面板RPC显式拒绝代理bootstrap，即使某份bundled面板清单声明该路径；插件通过宿主原有RPC执行业务，无法获得宿主令牌。控制台的手动恢复入口继续服务异常环境，不作为正常本机打开页面的前置步骤。

首次加载遇到网络/5xx故障且尚无面板时，默认恢复界面隐藏令牌输入，每1.5秒串行重试，网络恢复或页面回到前台立即重试；后台暂停该界面的重试。SSE也保持退避重连，成功后移除恢复界面。服务器明确拒绝或不支持bootstrap（403/404/405），或显式错误令牌尚未通过验证时，仍使用手动诊断路径。clear/dispose取消界面计时和监听，迟到回复不能重新挂载。该补充没有放宽任何HTTP来源、令牌或插件权限守卫。
