# 反馈草稿的本机保存

恢复旧版取消后继续编辑、跨页和重新启动后读取已保存草稿的行为。独立默认`console.feedbackDraft`控制器提供get/put/remove；固定GET/PUT/DELETE `/api/community/feedback-draft`经现有认证、来源和重置守卫，仅默认社区面板声明这三个资源。没有任意存储键、文件名、宿主令牌或新的通用RPC。

草稿保存在当前dataDir的固定feedback-draft.json。内容仅含原始昵称、正文和已接受截图，限制32/5000字符、9张、总JSON不超过2MiB-64KiB。截图验证四类规范base64及格式签名，完整解码仍由原浏览器流程负责。构造惰性，目录不可用只在消费时503；文件损坏、不可读、非普通文件或超限不会当空档覆盖。

PUT/DELETE携带读取时的32位十六进制不透明revision。每次同步重读并比较，唯一临时文件写入、同目录rename成功后才回执；失败保留原档。删除写新版本墓碑，旧回执不能复活清空内容。生命周期结束拒绝新写，数据重置沿现有全局闸门。并发保证依赖当前单个持锁内核，不宣称独立进程间的文件CAS。

`feedback-draft-state.js`将本地输入与确认回执分开：300ms合并保存，关闭/Escape立即移除弹窗并flush，后续输入不被旧GET/PUT覆盖；409保留当前输入，只有明确比较选择才采用已读版本。已保存草稿跨iframe及独立应用重启恢复；失败且未确认的内容仅在存活面板模型中保留，不承诺写盘失败后仍能跨销毁恢复。没有跨源导入旧localStorage的路径。

预览、明确公开确认、宿主验证码及`result.ok===true`仍是原发布条件。取消/失败保留稿，成功仅清除实际发布的版本，另一窗口或较新输入不被旧成功删除。截图移除及“清除本机草稿”继续用两击危险视觉；清除只在回执后显示成功。验证码、令牌、凭据及“已经确认发布”状态不持久化。
